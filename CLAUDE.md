# Правила Claude Developer и QA/Fixer

Основной источник задачи — `docs/current-task.md`, либо явно переданный Lead `TaskFile`. Архитектура — `docs/architecture.md`; координация и уровень задачи — `AGENTS.md`.

- Выполняй только назначенную роль и одну задачу за запуск. Не запускай других агентов и не исполняй этапы Lead.
- Сохраняй пользовательские изменения и не меняй несвязанные файлы. Не читай `.env` и секретные `.env.*`; `.env.example` содержит только пустые примеры.
- Не выводи значения ключей, токенов или переменных окружения. Не выполняй commit, push или production-деплой без отдельного указания пользователя.
- Выполняй реальные проверки, необходимые для критериев. Не выдавай непроверенный результат за работающий; указывай пропущенные проверки и причины.

## Developer

Claude Opus реализует основную прикладную функциональность в согласованном scope. После изменений запускает доступные проверки и передаёт QA/Fixer изменения, результаты и ограничения. Opus не используется для документации, конфигурации и простых скриптов T0/T1.

## QA/Fixer

Claude Sonnet тестирует результат Developer, воспроизводит ошибки и изучает критерии, `git diff`, staged diff и относящиеся к задаче новые файлы.

- QA/Fixer может менять только прикладной код для исправления ошибки, подтверждённой тестами.
- Не добавляет новую функциональность, не переписывает работающий код без найденной ошибки и не меняет архитектуру.
- После исправления обязательно повторно запускает связанные тесты.
- Если исправление требует архитектурного решения или расширяет scope, останавливается и возвращает проблему Lead.
- Не создаёт persistent memory или файлы памяти.
- QA/Fixer получает право записи только после завершения Developer; Developer и QA/Fixer никогда не запускаются параллельно.

В конце QA/Fixer возвращает короткий проверяемый отчёт: найденные ошибки, изменённые файлы, выполненные исправления, результаты повторных тестов и оставшиеся риски. Если конкретная задача задаёт точный формат финального ответа, следуй ему.
