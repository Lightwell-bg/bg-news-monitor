# NEWS-MVP-001 — вертикальный сценарий Flagman

## Цель

Реализовать только для главной Flagman: получение списка → извлечение новой статьи → дедупликация → AI-оценка → карточка в личный Telegram → подтверждение → публикация в канал.

## Scope

- `flagman`, главная страница, SQLite/SQLAlchemy 2/aiosqlite;
- нормализация URL, content hash, правила до AI;
- OpenRouter HTTP с Pydantic-валидируемым ответом;
- aiogram-карточка, callback и канал после подтверждения;
- планировщик с интервалом источника.

## Не входит

Другие источники и разделы, реальные внешние обращения в тестах, автопубликация, веб-модерация и внешняя БД.

## Критерии приёмки

- HTML-тесты используют локальные fixtures.
- Тесты не публикуют реальные сообщения.
- AI-ответ валидируется Pydantic-схемой.
- Некорректный AI JSON не публикуется.
- Повторное нажатие кнопки не создаёт второй пост.
- Токены отсутствуют в коде и логах.
- Исходная ссылка присутствует в публикации.
- Русский текст не содержит придуманных фактов.
- Полный текст чужой статьи не копируется.
- Только `TELEGRAM_ADMIN_IDS` используют управляющие кнопки.
- AI не имеет прямого пути публикации; решение администратора проверяет код.

## Проверки после реализации

`pytest` с fixtures и fake HTTP/Telegram/AI; тесты статусов, дедупликации, повторного callback, авторизации и корректного/некорректного AI JSON; статическая проверка конфигурации и секретов.

## Статус постановки

Код, fixtures и тесты ещё не созданы. `flagman` остаётся `enabled: false` до реализации его адаптера.

# NEWS-ADMIN-002 — управление источниками через Telegram и BG24

## Цель

Администратор управляет настройками источников из Telegram: включает и выключает источник, меняет интервал, разделы, inclusion topics и exclusion topics. Источник BG24 получает рабочий адаптер списка и статей.

## Scope

- Admin-only команда и inline-панель списка источников; авторизация только через `TELEGRAM_ADMIN_IDS` с сохранением существимой обратной совместимости `TELEGRAM_ADMIN_ID`.
- Просмотр текущей конфигурации источника; включение/выключение; изменение `min_interval_minutes`; просмотр, добавление и удаление разделов; просмотр, добавление и удаление inclusion/exclusion topics.
- Строгая Pydantic-валидация до сохранения. Идентификаторы, URL и структура YAML не должны становиться некорректными; сообщения об ошибках не содержат секретов.
- Безопасная запись только в путь `Settings.sources_file`, с атомарной заменой файла и сохранением валидного YAML. Никакой работы с `.env`.
- Новые настройки применяются процессом без дублирования задач планировщика; если изменение нельзя применить безопасно в рантайме, интерфейс должен явно сообщить администратору о необходимости перезапуска, а конфигурация всё равно сохраняется валидно.
- Реализовать `bg24_homepage` adapter и локальные HTML fixtures/tests для списка и статьи. Никаких реальных HTTP-запросов в тестах.

## Не входит

Управление Telegram/OpenRouter-настройками, редактирование токенов, произвольный YAML-редактор, публикация без модерации, сетевые запросы в тестах, commit/push/deploy.

## Критерии приёмки

- Неадминистратор не может увидеть или изменить настройки источников; callback защищён router filter и сервисной проверкой.
- Администратор может изменить каждый заявленный тип настройки через команды и inline-кнопки; после перезапуска `load_sources` читает сохранённое значение.
- Невалидный интервал, URL или пустой topic/section отклоняется без изменения файла.
- Сохранение не повреждает `sources.yaml`; тесты моделируют ошибку валидации и подтверждают сохранение прежней конфигурации.
- Изменение enabled/interval не создаёт дублирующихся scheduler jobs.
- BG24 listing извлекает только локальные валидные article links, article adapter извлекает заголовок/дату/тело или безопасно возвращает `None` при неполном HTML.
- Полный pytest, compileall и `git diff --check` выполняются после реализации.

## Проверки

Локальные pytest с fake Telegram и temporary `sources.yaml`; локальные fixtures BG24; тесты авторизации, callback, валидации, атомарной записи, scheduler reload и отрицательных сценариев. Внешние Telegram, OpenRouter и сайты не используются.

# NEWS-ADMIN-003 — понятная inline-панель и настройка порога важности

## Цель

Убрать из пользовательской Telegram-панели технические source id и справку с командами. Всё штатное управление источником выполняется inline-кнопками; добавление разделов и тем — в пошаговом диалоге. В панели настроек доступен текущий `IMPORTANCE_THRESHOLD` и его изменение.

## Scope

- `/sources` открывает короткий читаемый список кнопок с названием и статусом источника, без id, команд и технической справки.
- Карточка источника показывает понятные поля и inline-управление: включить/выключить, интервал, разделы, inclusion topics, exclusion topics. Пользователь не вводит source id.
- Добавление раздела/темы запускается кнопкой и завершается безопасным пошаговым вводом сообщения; отмена доступна кнопкой. Удаление остаётся inline.
- Добавить главную кнопку/экран «Настройки» и inline-управление порогом важности `IMPORTANCE_THRESHOLD` с текущим значением. Значение валидируется 0–100, применяется текущему процессу и сохраняется без чтения или раскрытия прочих `.env` значений.
- Все новые управляющие действия admin-only, callbacks ограничены Telegram 64 bytes, сообщения остаются в лимите Telegram и не содержат секретов.

## Не входит

Произвольное редактирование `.env`, отображение source id в пользовательском UI, изменение токенов/OpenRouter/Telegram-параметров, сетевые запросы в тестах, commit/push/deploy.

## Критерии приёмки

- В обычном пользовательском сценарии не требуется знать или вводить source id.
- Из списка можно открыть любой источник, изменить enabled и interval кнопками, добавить/удалить section/topic, отменить незавершённый ввод.
- `IMPORTANCE_THRESHOLD` виден и изменяем только администратору; невалидные значения не применяются и не сохраняются.
- Неадминистратор не получает доступ ни к источникам, ни к настройкам; существующая модерация не регрессирует.
- Локальные тесты покрывают inline flow, состояние ожидания ввода, отмену, авторизацию и изменение порога; полный pytest, compileall и git diff --check успешны.
