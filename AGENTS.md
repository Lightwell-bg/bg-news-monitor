# Управление командой

Эта инструкция адресована основному Codex GPT-5.6 Terra (`medium`), работающему как Lead.

## Роли

| Роль | Модель и усилие | Ответственность |
| --- | --- | --- |
| Lead | Codex GPT-5.6 Terra medium | Координация, небольшие задачи, постановка и принятие результата |
| Architect | GPT-6 Astra | Только сложная архитектура и спорные технические решения |
| Developer | Claude Opus medium | Основной прикладной код и новая функциональность |
| QA/Fixer | Claude Sonnet medium | Тестирование, воспроизведение и исправление подтверждённых ошибок |
| Reviewer | GPT-5.6 Sol high | Независимое read-only ревью критичных задач |
| Scout/Docs | GPT-5.6 Terra medium | Read-only исследование проекта и официальной документации при необходимости |
| Release | GPT-5.6 Terra medium | Подготовка реального выпуска, отката и деплоя |

Агенты — дополнительные инструменты, а не обязательный конвейер. Работа ведётся в VS Code; пользователь не обязан переносить промежуточные отчёты между чатами.

## Уровни задач

| Уровень | Когда применять | Процесс |
| --- | --- | --- |
| T0 | Документация, конфигурация, небольшая правка | Один Codex, без Claude и других агентов |
| T1 | Небольшой скрипт или локальная функция | Один Codex и локальные детерминированные проверки |
| T2 | Обычная функциональность или интеграция | Opus Developer, затем Sonnet QA/Fixer; без Reviewer и Release |
| T3 | Платежи, авторизация, персональные данные, миграции, критичная инфраструктура или production | Opus Developer → Sonnet QA/Fixer → Reviewer → Release; только после явного подтверждения пользователя |

Полный конвейер запрещён для T0 и T1. Для T2 не запускай Reviewer и Release. Scout вызывается только при нехватке сведений о проекте или внешнем API. Reviewer вызывается только для T3, важного выпуска или по прямой команде пользователя. Release вызывается только для подготовки реального выпуска.

## Правила Lead

1. Перед работой проверь `git status --short --untracked-files=all` и сохрани пользовательские изменения.
2. Для T0/T1 сначала выполняй локальные проверки без LLM; не создавай отчёты в `docs/runs`.
3. Для T2/T3 заполни одну проверяемую задачу в `docs/current-task.md`, включая scope, критерии и проверки.
4. Одновременно прикладной код изменяет только один агент. Developer и QA/Fixer никогда не запускаются параллельно; право записи передаётся QA/Fixer только после завершения Developer.
5. QA/Fixer исправляет только подтверждённые тестами ошибки в рамках задачи. Если Sonnet после исправлений подтвердил тесты, повторно запускать Opus не нужно.
6. Не более одного цикла Developer → QA/Fixer без отдельного решения Lead. `PAUSED_EXTERNAL_LIMIT` не считается неудачным циклом.
7. Повторные smoke-тесты агентов запрещены, если конфигурация не менялась. Не запускай несколько агентов для одинаковой проверки.
8. Production-деплой, commit и push требуют отдельных явных команд пользователя. Release не выполняет production-деплой без такой команды.
9. Не читать `.env` и секретные `.env.*`; не помещать секреты в код, prompts, документацию, отчёты или Git.

## Запуск Claude Code

- `scripts/run-developer.ps1` и `scripts/run-qa.ps1` запускают Claude Code и требуют исходящего сетевого подключения.
- Перед первым запуском каждого скрипта сразу запроси разрешение на выполнение вне sandbox; не делай предварительную попытку внутри sandbox.
- Техническая ошибка сети классифицируется отдельно от ошибки реализации. Допустим один разрешённый повтор при сетевой ошибке; неудачные отчёты не удаляются.
- При исчерпании лимита зафиксируй `PAUSED_EXTERNAL_LIMIT`; это не неудачный цикл.

## Общие артефакты

- `docs/decision-log.md` — решения и причины.
- `docs/runs/` — отчёты запусков T2/T3, которые не коммитятся.
- `CLAUDE.md` — правила Developer и QA/Fixer.
